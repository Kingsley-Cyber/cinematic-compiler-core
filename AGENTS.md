# AGENTS.md — cinematic-compiler control protocol

> Generated by URCP, then adapted. Keep this short. The layer DAG lives in
> `kernel/layer_order.yaml`; architecture in `docs/`; task state in Beads + URCP.

## Session start
```bash
harness bootstrap --json      # recover repo/env/task/proof state (not from chat)
```

## Working protocol
- Before a non-trivial plan:  `harness context --mode PLAN`
- Before a refactor / interface / schema change:  `harness impact <target>`
- Task state lives in Beads + URCP (`BEADS_ACTOR=claude-code bd ...`), never in chat or this file.
- Before compaction / session end:  `harness checkpoint`
- Before claiming done:  `harness validate` then `harness proof status`

Completion is computed, never asserted — do not claim done until URCP reports
current required proof.

## Schema control (owner rule 2026-10-10)
- Every `schemas/**/*.schema.json` change is logged in `schemas/schema_log.jsonl`
  with `python -m kernel.schema_log record <file> --change ... --reason ... --decided-by ...`.
  The log is append-only; `tests/test_schemas.py` fails when a schema's bytes differ from its latest entry.
- Schemas are URCP contracts (`.control/contracts/`); a schema edit marks the contract dirty and needs fresh proof.
- `kernel/layer_order.yaml` is the single source for layers, edges and write ownership.
  A pass writes only the envelope paths its node owns.

## Layer discipline
- Build one layer per slice; each slice ends with tests green, the schema log updated and a checkpoint.
- No paid model API, no renders. Authoring goes through a host callback / IDE; post-generation stays `null`.

## Navigation
Graft and Graphify first (caches under ignored `.control-state/`), then read the exact lines:
```bash
DO_NOT_TRACK=1 graft --dir .control-state/graft build . --no-gitignore --no-ignore
DO_NOT_TRACK=1 graft --dir .control-state/graft skeleton <file> .
graphify update . --out .control-state/graphify
```

## Do not
- Do not manually crawl the repository when `harness context` or the graphs can supply bounded context.
- Do not edit `kernel/layer_order.yaml` or a logged schema to make work easier; a genuine conflict is a
  REQUIRES_DECISION for the owner, not a silent redesign.

## Authority
`SOURCE > DETERMINISTIC > DECLARED/HUMAN > DERIVED > LLM_INFERRED > UNKNOWN`.
Lower authority may enrich but never overrides higher; UNKNOWN is never "clear".
