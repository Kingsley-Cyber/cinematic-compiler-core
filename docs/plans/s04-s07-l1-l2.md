## 2. Schemas

Each is a new file under `schemas/graphs/`, logged in the schema log before code. Fields follow your
per-graph table ("Temporal: Event · precedes · timestamp · duration, gap", "Causal: Event · causes ·
event_type · causal_strength", "State: Entity-state · transitions_to · condition · trigger_event",
"Contact: Contact-event · precedes · contact_type (touch/grip/support/release) · body_part, object").
Times are seconds, as in the LBN keys.

### 2.1 Beat plan (authored at S04) — `beat_plan.schema.json`

```json
{
  "step_id": "S04", "band": "L1",
  "author": {"host": "Claude Code IDE", "model": "claude-opus-5-5", "packet_sha256": "sha256:…"},
  "beats": [{
    "id": "b01", "t": 0.0, "dur": 0.6,
    "event_type": "action | hold | transition",
    "label": "staff_raise",
    "participants": [{"kind": "entity|prop|surface", "id": "wizard"}],
    "action": "Wizard plants the staff and raises the free hand. NOT a strike.",
    "requires": [{"subject": "staff", "property": "holder", "value": "wizard"}],
    "effects":  [{"subject": "floor", "property": "damage", "value": "scorched"}],
    "contacts": [{"contact_type": "grip", "a": {"kind": "entity", "id": "wizard", "part": "right_hand"},
                  "b": {"kind": "prop", "id": "staff", "part": null}}],
    "causes":   [{"to": "b03", "causal_strength": "hard", "why": "the bolt needs the raised staff"}]
  }]
}
```

Rules: ids come from L0.5 (entities, props, surfaces); parts from their card `parts`; prop property values
from the object card `states`; `requires` is read at `t`, `effects` commit at `t + dur`.

### 2.2 S04 output — `temporal_graph.schema.json`

- `nodes.beats` items: `id, t, dur, event_type, label, participants, action, requires, effects` (copied from the plan).
- `edges.temporal` items: `id, from, to, relation (precedes|overlaps|starts_with), duration, gap` —
  `duration` = source beat `dur`, `gap` = `to.t − (from.t + from.dur)`; computed, never authored.

### 2.3 S05 output — `causal_graph.schema.json`

- `edges.causal` items: `id, from, to, relation (causes), causal_strength (hard|soft), why`.
- `/quadrant` (new top-level path owned by S05):
  `{causal: {branching, parallel_effects, prerequisites} (0–2 each), style: 0–2, quadrant: A|B|C|D, strata: [1..4]}`.
  Scoring is deterministic: parallel = max fan-out (1→0, 2→1, 3+→2); prerequisites = hard edges (0→0, 1–2→1,
  3+→2); style from intent style_reference + genre + authored hold/transition beats. Quadrant and strata follow
  your table (0–2 = D, 3–4 = B or C by the style score, 5–6 = A; stratum 1 always, 3 if any causal score > 0,
  2 if style > 0, 4 if stratum 3 and quadrant A).

### 2.4 S06 output — `state_graph.schema.json`

- `nodes.states` items (entity-state): `id, subject, property, value (condition), from_t, to_t, set_by (beat id | initial)`.
- `edges.state_transition` items: `id, from_state, to_state, trigger_event (beat id)`.
- Initial states: prop values from the plan's first `requires` or the card's first listed value? → **default:
  only from `requires`/`effects`; an unknown starting value stays `unknown`, never assumed.**

### 2.5 S07 output — `contact_graph.schema.json`

- `nodes.contacts` items (contact-event): `id, t, contact_type (touch|grip|support|release), a {kind,id,part}, b {kind,id,part}, beat`.
- `edges.contact` items: `id, from, to, relation (precedes|releases)` — `releases` links a release to the
  grip/support it ends.

## 5. Decisions (owner, 2026-10-10)

1. **Beat author:** owner had no preference → Claude writes beat plans in-session (IDE); no paid API. The plan
   carries `author` and the `packet_sha256` of the exact packet it was written from; S04 refuses a mismatch.
2. **Branching:** linear only for now. No alternative fields exist; the branching score is always 0.
3. **State vocabulary:** closed kernel list in `kernel/state_vocabulary.yaml` (kernel log):
   - actors: `support` (grounded, airborne, braced, lying), `posture` (standing, crouching, kneeling, prone,
     supine, inverted), `possession` (a prop id or none), `condition` (ok, staggered, stunned, down),
     `location` (a surface id);
   - props: their object card `states`, plus `holder` (an entity id or none) and `location` (a surface id);
   - surfaces: `damage` (none, marked, scorched, cracked, cut).
   Any other property or value is refused.

## 6. Defaults taken while detailing (owner may veto)

- Contact events happen at their beat's end (`t + dur`), like effects. Touch is instant; grip/support stay
  active until a release of the same pair.
- Initial state of a property = the value its first `requires` asserts; otherwise `unknown`.
- `possession` names one prop; an actor holding two props is a known limit of v1.
- Style score (0–2) proxy: +1 for an intent `style_reference`, +1 for any hold beat.
- Parallel-effects score uses the most consequences of one beat (effects + outgoing causes): 0–1 → 0, 2 → 1, 3+ → 2.
- The end-to-end example adds one draft object card, `staff`, to the library (logged).
